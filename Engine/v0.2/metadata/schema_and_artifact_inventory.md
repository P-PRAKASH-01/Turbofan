# ENGINE-TWIN v0.2 schema and artifact inventory

This inventory describes the existing v0.2 artifacts. It does not regenerate or modify them. SHA-256 values are lowercase hexadecimal digests of the files present when this inventory was prepared.

## Dataset scope and limitations

| Item | Value |
|---|---|
| Version | 0.2.0 |
| Raw samples | 115,200 rows |
| Scenarios | 960 |
| Synthetic engine parameter sets | 30 |
| Samples per scenario | 120 at 1-second intervals |
| Fault classes | 8 |
| Model features | 39 |
| Label-table columns, including row key | 9 |

The dataset is generated by a synthetic, assumption-driven quasi-steady surrogate with simplified thermal response. It is **not a validated real-engine digital twin**, nor calibrated to DRDO, a manufacturer, or any particular engine. It is intended for synthetic workflow prototyping only. Its classification results measure performance against labels produced by this simulator and do not establish real-engine accuracy. There is no defensible health-index or end-of-life model: `rul_hours` is unpopulated. Engine and fault-response parameters are assumptions, not verified engine specifications. It is not suitable for flight, maintenance, safety-critical decisions, or operating limits. See `README.md`, `config/dataset_config.json`, `metadata/data_dictionary.csv`, and `metadata/parameter_register.csv` for equations, definitions, and assumptions.

For each sensor channel, the table contains its simulated observation, a residual calculated as observation minus the corresponding simulator-provided healthy reference, and a missingness indicator. Phase columns are one-hot encodings. The healthy references are simulator outputs; these features are not yet an inference pipeline for real sensor streams.

## Label and lineage schemas

`data/processed/labels.csv` has 115,200 rows and these columns in file order:

```text
feature_row_index
is_fault
fault_type
fault_severity
fault_active
fault_onset_s
fault_duration_s
sensor_fault_target
rul_hours
```

`feature_row_index` aligns each label row to the matching feature row. The remaining columns are targets or target metadata; `rul_hours` is null. None of these columns belongs in the model feature matrix.

`data/processed/feature_lineage.csv` has 115,200 rows and columns:

```text
feature_row_index, raw_row_index, scenario_id, engine_id, operating_phase,
engine_split, scenario_split, time_s
```

This metadata maps each feature row back to a raw row and its scenario, engine, time, and split membership. It is not a predictor table.

The scenario partitions split scenarios belonging to the 18 training engines; those engine identities therefore recur across scenario partitions. The engine-held-out partitions use disjoint engine identities. Each protocol has its own split files and should be interpreted separately.
